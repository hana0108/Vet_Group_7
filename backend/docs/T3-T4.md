# T3 y T4: inyección de dependencias y configuración

## T3. Composition root manual

`container/compositionRoot.js` es el único punto de composición del backend. Crea el pool MySQL, los cuatro repositorios, servicios y controladores, y construye los routers entregándoles sus dependencias. Las rutas y las capas de negocio no importan `config/db.js` ni crean pools. `app.js` consume los routers y el pool a través del contenedor; las pruebas pueden inyectar un pool simulado.

Se eligió un contenedor manual en lugar de Awilix porque el proyecto usa CommonJS y tiene un grafo pequeño y explícito. El contenedor muestra directamente cómo se relacionan las capas, evita añadir una dependencia de runtime y hace sencillo sustituir el pool en pruebas. Awilix sería útil si el sistema necesitara registros dinámicos o ciclos de vida de dependencias más complejos.

## T4. Configuración y errores

`server.js` carga `backend/.env` y valida la configuración antes de iniciar HTTP. `config/env.js` requiere `DB_HOST`, `DB_USER`, `DB_NAME`, `PORT` y `SESSION_SECRET`; `DB_PASSWORD` debe estar definida aunque pueda ser vacía para MySQL local. Valida el rango del puerto y los orígenes completos de `CORS_ORIGINS`. En producción, `SESSION_SECRET` debe tener al menos 32 caracteres y no ser repetitiva.

`app.js` limita CORS a `CORS_ORIGINS`, usa cookies de sesión `httpOnly` y `sameSite: 'lax'`, y activa `secure` en producción. `middleware/error-handler.js` proporciona respuestas JSON para rutas inexistentes y errores no gestionados, sin exponer detalles internos de errores 5xx.

## Ejecución

1. Copia `.env.example` a `.env` dentro de `backend` y ajusta las variables para tu instancia de MySQL. Mantén `DB_NAME` igual a `DB_SETUP_NAME` si vas a usar el instalador.
2. Ejecuta `npm ci` y luego `npm test` desde `backend`.
3. Ejecuta `npm start` y consulta `http://localhost:3000/api/health` para comprobar que la aplicación puede ejecutar una consulta contra MySQL.

`scripts/db-setup.cjs` instala el esquema en una base vacía indicada por `DB_SETUP_NAME` y protege las bases `vetgroup7_db` y `vetgroup7_fase4_test`. No es necesario ejecutar el archivo `database/schema.sql` directamente para esta configuración.

El archivo `.env` contiene credenciales privadas y está excluido por Git; publica solo `.env.example`.
